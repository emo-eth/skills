# Wall Clock Handoff - 2026-08-11

## Glossary

- **Pi**: The `@earendil-works/pi-coding-agent` native host.
- **OMP**: The `@oh-my-pi/pi-coding-agent` native host.
- **Agent Plugin**: The portable package rooted at `plugins/wall-clock/plugin.json`.
- **MCP**: Model Context Protocol, included as an optional operation surface but not an enforcement mechanism.
- **Expiry policy**: The required choice between blocking new work and also aborting supported running work.

## Pick up the branch

From an existing checkout:

```sh
git fetch origin
git switch wall-clock
git pull --ff-only origin wall-clock
cd plugins/wall-clock
npm install
npm run check
npm test
npm audit --omit=optional
```

From a checkout without the local branch:

```sh
git fetch origin
git switch --create wall-clock --track origin/wall-clock
```

Do not run `omp plugin link --dry-run` to inspect this package. OMP 17.2.15 creates a global plugin link even with `--dry-run`.

## Run the native adapters

Use absolute paths from the checkout:

```sh
pi --extension /absolute/path/to/plugins/wall-clock/src/pi.ts
omp --extension /absolute/path/to/plugins/wall-clock/src/omp.ts
```

Inside either host:

```text
/wallclock start 30m block-new
/wallclock status
/wallclock stop
```

Select `abort-running` instead of `block-new` only when supported running native work must stop at expiry. Unknown or unabortable executors are rejected before they start.

## What is implemented

- Explicit duration or next local-time activation with a required expiry policy.
- Active, wrap-up, expired, and complete phases.
- Host-measured current, total, inference, tool-call, remaining, and assignment elapsed time before model turns.
- Native pre-action blocking for wrap-up, expiry, and completed assignments.
- Observed cancellation for supported Pi and OMP executors.
- One action per native host abort domain under `abort-running`, while OMP parent and child sessions can run together.
- Bounded assignments with objective, scope, acceptance targets, ceiling, wrap-up, status, and actual elapsed time.
- Structured reports with evidence, partial and skipped work, validation, shortcuts and tradeoffs, risks, unknowns, and one parent action.
- Report-linked plan revisions with complete, partial, blocked, and deferred plan states.
- OMP child binding, child context, parent persistence, terminal fallback reports, and child isolation.
- Version 3 durable state with deep newest-entry validation and fail-closed restore.
- Agent Plugins discovery, bundled skill, optional MCP tools, and native package manifests.

## Known boundaries

- Pi does not create a native child through this adapter.
- OMP requires one active unbound assignment for each task invocation. Batch and nested delegation are blocked.
- Direct `user_bash` and unknown extension tools are rejected under `abort-running` because their cancellation cannot be proved.
- Remote provider cancellation is not implemented.
- Codex and Claude package discovery is allowed, but activation remains deferred until an open native enforcement seam is tested. Claude proprietary systems remain excluded.
- Standalone MCP refuses activation and does not mirror native session entries.
- Full `npm audit` reports five high-severity findings through optional OMP model and image dependencies. `npm audit --omit=optional` reports zero findings.
